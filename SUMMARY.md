# Sign, notarize and staple the release artifacts (#988)

#988's decision was already taken and recorded on 2026-08-18 (`docs/plans/2026-08-18-release-roadmap.md`, Option B — signed and notarized), so this is the second half the issue names: a release chain in the `Makefile` that turns a built bundle into a signed, notarized, stapled `.app` + `.dmg` and a signed, notarized standalone CLI archive staged in `dist/`, plus the checklist and pitfalls as a plan doc and the design rule in `CLAUDE.md`. `make app` and `make dist` stay unsigned and unchanged — they never leave the machine that built them, which is exactly why they are fine and a download is not. Every new target **refuses rather than degrades**: no `SIGN_IDENTITY` is an error and never an unsigned artifact, because the failure worth preventing is the quiet one, the `.dmg` that built fine and reached a link unsigned. The targets are `check-signing`, `check-notary`, `release-bundle`, `sign`, `notarize`, `dmg`, `notarize-dmg`, `verify-release`, `check-clean-tree`, `release` and `release-clean`; signing is inside-out and never `--deep`, the standalone CLI is a *copy of the signed seed* rather than a second signing act (so it and `Contents/Helpers/tasks` are byte identical), `stapler` is the gate rather than `notarytool --wait`, and `dmg` refuses unless the bundle already validates.

The one change to existing behaviour is that `release-bundle` assembles the release bundle with the *same* `app-install`/`dist-install` recipes as the dev bundle, overriding `APP_BUNDLE` on the sub-make command line — so the artifact that is downloaded cannot quietly differ from the one that was tested. Riding along with that, `app-install`'s two guards (the unset-`HOME` refusal and the "Tasks is running" note) are now gated on one shared comparison against the default bundle path, since neither has anything to say about an absolute override; both are otherwise unchanged, and the `HOME` guard still fires exactly where it did. `docs/plans/2026-08-19-signing-and-notarization.md` carries the artifact table, the three-part answer to the CLI question (nested seed → notarized with the app; bare Mach-O cannot be stapled; online ticket acceptable *for a reason specific to this system*, since nothing here works offline), the pitfalls, the #1003 payoff, and a checklist split into a block that needs no Apple account and a block gated on enrollment. The quarantine propagation through `std::fs::copy` is written as **confirmed** and promoted to a numbered checklist gate that must pass before any download link is published; `install_binary` is deliberately unchanged.
